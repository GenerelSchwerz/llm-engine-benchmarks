# LLM engine benchmark workspace

- Read `RUNBOOK.md`, `uv run scripts/suite_store.py show SUITE`, the suite matrix, and each selected engine guide. The TUI selects IDs; the preparation agent resolves exact versions and compatibility.
- For a TUI setup request, read `uv run scripts/catalog_cli.py show-request REQUEST_ID` and use `list-engines` or `list-models` first. Verify an existing install and use `catalog_cli.py use-existing REQUEST_ID ITEM_ID`; do not reinstall it. Use `add-engine`/`add-model --request-id` for new entries, `update-engine`/`update-model ITEM_ID --request-id` for changed entries, and `remove-engine`/`remove-model ITEM_ID --request-id` for removals. A built-in engine update writes a local revision and checkout override; uninstalling its checkout leaves the shared manifest definition available. Custom catalog removal leaves files in place unless the user explicitly asks to uninstall them; then use `--delete-install --confirm-path EXACT_SAVED_PATH`. Check all exit codes. After handling every requested item, run `catalog_cli.py finish-request REQUEST_ID --message 'Verified summary'`; the TUI polls and validates this while the interactive agent remains open. In monochrome log mode, also return JSON matching `manifests/setup-response.schema.json` with `ready` and every surviving result ID (an empty list is valid for removal-only requests), or `needs_input` plus concrete questions. The TUI validates results and recorded removals before confirmation.
- Write preparation findings through `scripts/suite_store.py record-engine`, `record-model`, and `record-packet`. Run `validate` then `freeze`; after the handoff is complete, run `finish-prepare SUITE --message 'Verified summary'`. Check exit codes and correct rejected records; never claim a suite is frozen after a failed write. The completion signal lets the outer TUI report that preparation finished while the interactive Codex terminal remains open.
- Use `uv run scripts/<name>.py` for this repository's Python entry points. The pinned llama-benchy package is installed from `uv.lock`.
- Keep source, build, runtime environment, model artifacts, commands, result, and revision separate for every engine.
- Research agents report exact per-engine/per-model command packets. The coordinator freezes a plan; one execution agent runs it on each machine.
- Use coherent generation and the pinned llama-benchy track when its chat protocol is supported or adapted. Record an explicit unavailable result otherwise.
- Validate source revisions, actual executable flags, model loading, output coherence, and intended optimization telemetry before measuring throughput.
- Preserve raw commands, prompts, outputs, logs, benchmark JSON, memory samples, errors, and teardown. Mark failed and slower cases.
- Never publish private model artifacts, credentials, personal prompts, or raw captures that contain private data.
